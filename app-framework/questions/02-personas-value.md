# Bank 2 · Personas and value (V)

Used in: [02 Personas and value](../playbook/02-personas-value.md).
Read [00-etiquette.md](00-etiquette.md) first. ★ = must-ask (V1–V5). **(Rec)** = recommended default.

| ID | Question | Why it matters | Options (Rec first) | Ask when |
|---|---|---|---|---|
| V1 ★ | Which personas use it? Confirm the list and a one-line description of each. | Every page is reviewed against these personas. | Specialist/analyst + Business owner + Production support + Finance **(Rec)** · Custom list | always |
| V2 ★ | For each persona, what are the top 3 jobs or questions they bring to the app? | Jobs drive the page inventory and the key numbers. | Draft per persona for the user to correct **(Rec)** · User supplies them | always |
| V3 ★ | What would each persona find *concerning*? What should jump out at them? | It defines alerts, highlights, sort orders and "needs attention" panels. | Draft per persona (e.g. at capacity, failing, idle, overspend) **(Rec)** · User supplies | always |
| V4 ★ | What tone and wording rules apply (framing, banned words, verdict labels)? | It keeps copy consistent across every page and every agent. | Growth framing with positive verdicts **(Rec)** · Neutral · Customer's glossary | always |
| V5 ★ | Should the UI change per persona: a persona switch, separate views, or one view for all? | It has a big effect on layout and component design. | One page with a persona switch that reorders and highlights **(Rec)** · Separate pages per persona · Single view | always |
| V6 | Which persona is primary, i.e. who wins when layouts conflict? | It breaks design ties. | The specialist/analyst **(Rec)** · Business owner · Exec | if there are 2 or more personas |
| V7 | Write the value stories: "As <persona>, I can <do> so that <outcome>." Which 3 matter most? | Value stories become the P0 list and the demo script. | Draft the top 3 per persona **(Rec)** · User writes them | always |
| V8 | What does each persona do *next* after seeing a concerning item (drill down, open the source system, export, notify)? | It defines cross-links and actions. An insight that dead-ends is worth little. | Drill down, then link to the source system **(Rec)** · Export · In-app action | always |
| V9 | Which domain terms must match official names exactly (product names, plan or license types, units of measure)? | Mismatched terms cause trust and support problems. | The vendor's official names; the full name in headings **(Rec)** · Customer's terms | if there is a vendor or customer domain |
| V10 | Is there a fixed ordering convention (cost order, severity order)? | It keeps lists, legends and charts consistent everywhere. | Most to least costly or severe **(Rec)** · Alphabetical · By volume | if there are categories |
| V11 | Which personas must *not* see certain data or actions? | It feeds access control ([bank 5](05-integration-security.md)) and hides admin-only controls. | Admin-only actions hidden from others **(Rec)** · Everyone sees everything | if there are admin or write actions |
| V12 | How technical is each persona? Do they need definitions or tooltips on every metric? | It sets how much help text to write and how dense the numbers can be. | A tooltip with a plain-language definition on every metric **(Rec)** · Expert UI, minimal help | always (quick) |

**Close the bank:** fill the Persona Sheet ([templates/persona-sheet.md](../templates/persona-sheet.md))
and put the persona table at the top of the Board.
